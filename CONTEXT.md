# CONTEXT

Устойчивый общий язык проекта: сущности, термины, инварианты, ссылки на ключевые области кода.

> Чем отличается от ADR: сюда — что означают термины и где логика; в `docs/adr/` — почему принято решение. Замысел и дорога — в `docs/VISION.md` и `docs/ROADMAP.md`.

## О продукте в одной фразе

arch_forge (опирается на идеи прототипа `archlens`, но код — свой) статически разбирает чужие микросервисные проекты (полиглот, в первую очередь C#/.NET) и строит живую многоуровневую карту архитектуры — «плашки» и связи в стиле Unreal Blueprints. Локально; целевой код не покидает машину.

## Термины

### Карта и узлы
- **Целевой проект (Target)** — анализируемый чужой проект; только читаем.
- **Сервис (Service)** — микросервис: папка + точка входа (или compose/k8s-манифест). Единица верхнего уровня.
- **Слой (Layer)** — уровень чистой архитектуры (Domain/Application/Infrastructure/Api/Contracts…); обычно = проект.
- **Блок (Block)** — стереотип-группа внутри слоя (Entities, Handlers, Validators, Endpoints…).
- **Тип / Член (Type / Member)** — класс/record/интерфейс/enum и их поля/методы.
- **Плашка / Узел (Node)** — визуальный элемент; `kind: service|layer|block|type|member` (+ `datastore|topic` как инфра). **Библиотеки — не узлы.**
- **Связь (Edge)** — `depends · http-call · publishes/subscribes · rw-db · layer-ref · holds · implements · raises · handles · uses`.
- **Якорь на исходник (Source Anchor)** — стабильная ссылка узла на код (проект/файл/символ). Для «клик → код» и контекста ИИ. Обязателен.
- **Карта (Map)** — итоговый граф (React Flow).
- **Импорты / тяжесть (Imports / Heaviness)** — прямые + транзитивные библиотеки за кнопкой «Импорты»: дерево, размер, дубли версий, «кто ещё использует».

### Картина системы (Фаза 1.5–1.6)
- **Система (System)** — набор сервисов + инфраструктура (БД, шина, внешние системы), разобранный по компоновочным манифестам (docker-compose) и коду. Уровень L0 карты. `adr/0011`.
- **Среда (Environment)** — dev/stage/prod: именованный набор compose-файлов (`docker-compose.<env>.yml` поверх базового); выбирается `?env=`. Порты, сети, healthcheck и рёбра зависят от среды.
- **Хранилище / Топик / Внешняя система** — узлы `datastore` (БД, кэш), `topic` (шина), `external` (сторонний сервис). Не сервисы проекта.
- **Провенанс (Via, Provenance)** — откуда взят факт: `compose` / `config` / `code`; вместе с `confidence` и якорем на исходник отвечает на вопрос «почему ты так решил». Сквозной инвариант UI.
- **Уверенность (Confidence)** — число 0..1 на ребре/факте: типизированный клиент > строковый литерал > собранный из переменных.
- **Call-graph (граф вызовов)** — список конкретных HTTP-вызовов (`EdgeDto.Calls`: метод, маршрут, `файл:строка`) на ребре `http-call`, найденных Roslyn в коде. Опционален: `?calls=`.
- **Проблема (Problem) / Детектор (Detector)** — находка уровня системы (общая БД, цикл сервисов, висячее событие, БД наружу, DTO-маппинг, дрейф, нарушение слоёв) и код, который её ищет. Главный сигнал карты.
- **Здоровье (Health)** — rollup числа и серьёзности проблем в scope (система/сервис/слой); показывает, куда проваливаться.
- **Деградация (Degradation)** — явная пометка «не удалось разобрать часть» (`adr/0008`); неоднозначное не выдумываем.
- **Пер-сервисный compose** — compose в папке самого сервиса. Код-линзы (дрейф, слои, call-graph) идут только по сервисам со своим compose; монорепо с одним корневым compose пока даёт пустой результат (известный пробел).

### Классификация и робастность
- **Стереотип (Stereotype)** — роль типа: Command/Query, Validator, Endpoint, Handler, Aggregate, Value Object, Domain Event, Port, Repository, DbContext, Controller…
- **Convention-pack** — формализованные правила команды: `маркер → стереотип`, состав среза, направление зависимостей. Встроенный дефолт + пользовательский: файл `archforge.conventions.json` (или `.archforge/conventions.json`) ищется от пути анализа вверх по дереву и мержится поверх дефолта (секции `markers`, `fallback`, `expect`, `dtoMapping`). `adr/0007`.
- **Профиль / уровень настроек (планируется)** — набор порогов и правил по масштабу проекта (малый → полный свод платформы), настраиваемый через UI. Пока не реализован; см. `docs/ROADMAP.md`, «Планируется».
- **Дрейф / линт (Drift)** — отклонение кода от convention-pack (напр. хендлер без `ICommandHandler`).
- **Покрытие (Coverage)** — доля классификации по маркерам / эвристике / `unknown`. Честность вместо догадок. `adr/0008`.
- **Тиры разбираемости** — пол (структура + связи, всегда) → эвристики → маркеры (точно + линт). `adr/0008`.

### Фаза 2 (ИИ)
- **Контекст-бандл** — набор по плашке для ИИ-агента (код + правила слоёв + инструкция).
- **Агент-раннер (IAgentRunner)** — запуск ИИ поверх локального CLI/модели (Claude/Codex/…); приложение агностично к подписке. `adr/0005`.

## Инварианты

### Чистая архитектура
- Domain не зависит ни от кого; зависимости — всегда внутрь, к Domain. Нарушение = кандидат в линт.

### Продуктовые
- Целевой код не покидает машину.
- Разбор только читает; запись — лишь с явным апрувом (Фаза 2).
- Всегда отдаём хоть что-то (пол); неоднозначное → `unknown`, не выдумываем.
- Библиотеки не рисуем в графе — только за кнопкой «Импорты».

## Движок

Разбор C# — **Roslyn** (`docs/roslyn.md`): семантика на собираемых проектах + синтаксический «пол» на несобираемых. `adr/0009`.

## Ключевые области кода

Бэк — .NET solution по своду: сервисы `Analysis` (Roslyn: путь→IR) и `Map` (проекции/гейтвей/API), каждый — Domain/Contracts/Core/Infrastructure/Web; общий шов — `ArchForge.Contracts`/IR (`adr/0009`). Фронт — свой клиент React + React Flow (`adr/0010`). archlens (Node/TS) — только референс идей.
