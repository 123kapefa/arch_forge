# VISION — arch_forge

Северная звезда: что строим, зачем, в каком порядке. Решения — в `docs/adr/`, дорога — в `ROADMAP.md`, словарь — в `../CONTEXT.md`.

## Отношение к archlens

arch_forge строится на **.NET по своду** (Clean Architecture), а archlens (Node/TS) — **референс идей** (IR-модель, «Импорты за кнопкой», раскладка), не кодовая база. Фронт — **свой клиент** на React + React Flow (`@xyflow/react`), не reuse archlens. Решения — `adr/0009` (бэк + декомпозиция) и `adr/0010` (фронт).

## Проблема

Понять чужой микросервисный проект тяжело: слои, сервисы, связи, инфра и CI разбросаны по манифестам и коду; текстовая документация устаревает.

## Замысел

Инструмент **сам** читает проект (полиглот, микросервисы) и строит живую многоуровневую карту: **система → сервис → слои → типы**, со связями. Сторонние библиотеки — не в графе, а за кнопкой «Импорты» (дерево + «тяжесть»).

## Кому и зачем

Онбординг, аудит архитектуры, живая документация, планирование изменений. Enterprise — приватный код через локальный агент (наружу только IR).

## Фазы

- **Фаза 1 — Видеть (read-only карта).** Навигация System→Service→Type, роли по маркерам, линт против свода, покрытие, импорты, фильтры. DoD — ниже.
- **Фаза 2 — Действовать (ИИ).** «Визуальный Claude Code»: выбрал плашку → инструкция → агент правит код → diff → карта обновилась. `adr/0005-ai-provider-adapter.md`.
- **Фаза 3 — Контроль.** Дифф/дрейф архитектуры между коммитами/PR, арх-линты в CI, шаринг.

## Definition of Done — Фаза 1

«Открываю любой локальный репо и хожу **System → Service → Type**: плашки с ролями, паутина связей типов, **линт отклонений от моего свода**, честное **покрытие** (маркеры/эвристика/unknown), импорты с тяжестью, фильтры/focus — всё локально, код не уходит.» Экран-эталон согласован (мокап главного экрана).

## Движок и классификация

- **Разбор C# — Roslyn** (движок; `docs/roslyn.md`): семантика (наследование, дженерики, ссылки) на собираемых проектах + синтаксический «пол» на несобираемых.
- Другие языки — позже, отдельными `Analysis`-сервисами с тем же контрактом `путь → IR`.
- **Convention-pack** — документированные правила команды (`маркер → стереотип`, состав среза, направление зависимостей) → точная классификация ролей + **линт дрейфа**. Источник пака — свод команды (напр. Obsidian). `adr/0007`.
- **Graceful degradation + честность покрытия** — всегда отдаём структуру и связи; роли — по маркерам / эвристике / `unknown`; неоднозначное не выдумываем. `adr/0008`.

## Узлы и связи

Узлы: `service · layer · block (стереотип) · type · member` (+ `datastore/topic` как инфра). **Библиотеки — не узлы.** Рёбра: `depends · http-call · publishes/subscribes · rw-db · layer-ref · holds · implements · raises · handles · uses`. Каждый узел несёт **якорь на исходник**.

## Монетизация — направление

Локальный агент (код не уходит) + SaaS/self-host; подписка на инструмент, ИИ — BYO (свой Claude/ключ) или через шлюз. Детали — открытый вопрос (см. archlens PLAN §9).

## Гарды на будущее

Модульные границы `analyzer / viz / agent-runner / entitlement`; стабильные якоря; конфигурируемость; локальность.
