## Красные тесты на внешний `auth_service`

Два теста Analysis читают локальный репозиторий `auth_service` (путь — переменная `ARCHFORGE_AUTH_SERVICE`, по умолчанию `~/Documents/projects/microservices/auth_service`). Если папки нет — тест честно пропускается (`SkippableFact`); если есть — сравнивает с числами, снятыми на старой версии таргета.

| Тест | Ожидание | Сейчас |
|---|---|---|
| `RoslynClassifierTests.Reproduces_spike_coverage_on_auth_service` | покрытие ≥ 90% | 316 из 455 (~69%) |
| `RoslynSemanticTests.Semantic_pack_leaves_no_unknown_on_auth_service` | 0 unknown | 139 unknown |

**Причина:** изменился сам таргет (история `auth_service` начата заново 2026-09-25; добавлен Keycloak, убраны OpenIddict и Razor Pages), а ожидания остались прежними. Код arch_forge при этом не менялся.

**Что делать:** привязать тесты к зафиксированной копии таргета (в репозитории или по тегу/коммиту) либо разобрать, какие новые типы не распознаются, и осознанно обновить пороги. Пока красные при наличии локального таргета; на CI без него — пропускаются.

## Монорепо: код-линзы пусты

`ServiceAnalyzer` запускает Roslyn только для сервисов с пер-сервисным compose. Для монорепо с одним корневым compose дрейф, слои и call-graph (`?calls=`) возвращаются пустыми, хотя узлы системы рисуются (fallback на корневой compose). Пробел G2-для-анализатора; см. `docs/tech/roadmap/epics.md` (E3.1).
