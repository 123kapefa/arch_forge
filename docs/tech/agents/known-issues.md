## Монорепо: привязка по имени и клиентские библиотеки

Монорепо с одним корневым compose поддерживается (issues #156, #159): сервисы по `.sln` привязываются к узлам по имени; вызовы клиентских библиотек (`*.Contracts`) приписываются потребителю, подключившему библиотеку прямой `ProjectReference` и вызвавшему её метод регистрации. Остаются ограничения: сервис без однозначного совпадения имени с узлом (общие/зонтичные решения, сильно расходящиеся имена) не анализируется; имена с префиксом компании или точками внутри слова (`Kalmykov.CommentService`) с узлом не совпадут (безопасный пропуск); транзитивные ссылки между библиотеками не прослеживаются; потребителю приписываются вызовы всей папки библиотеки (а не одного клиента); библиотека должна лежать внутри корня анализа и называться как клиентская (`*.Contracts`, `*.Client`…); имя метода регистрации, совпадающее с методом самого сервиса, не засчитывается; тело базового класса-обёртки (`BaseHttpClient.GetAsync`) не читается, вызов узнаётся по имени метода внутри зарегистрированного клиента. Смешанный случай (у части сервисов свой compose, у остальных нет): анализируются только сервисы со своим compose. Проблема «маппинг DTO не централизован» остаётся системной, а не пер-сервисной. Слой типа в разборе всего корня монорепо (конструирование DTO) считается от корня запроса: «test» в имени самого корня по-прежнему даёт слой `tests`.

## Символические ссылки

Разбор не следует по символическим ссылкам и не читает по ссылкам пути из содержимого проекта (issue #158, `SafeFiles`): код, подключённый в проект ссылкой на каталог вне него, не анализируется. Это сознательная цена безопасности (недоверенный проект не должен уводить чтение за свои пределы). Если понадобится, вынести в явную настройку. Остаются: проверка ссылки при перечислении и чтение файла разделены во времени (подмена между ними требует записи в папку проекта во время разбора; риск низкий); `GitBranch` в Map читает `gitdir:` из файла `.git` (путь произвольный, но читается только `HEAD`, виден лишь `refs/heads/…`); на Windows UNC-пути в `gitdir`, `env_file` отсекаются проверкой корня, но `gitdir` — нет (оценка, не проверялось); поиск `archforge.conventions.json` намеренно идёт до 12 уровней вверх за пределы корня (файл-ссылка при этом не читается).
