# 0016 — Архитектура фронта v2: модули по экранам, роутер, TanStack Query, `legacy/`

## Статус
Принято (2026-11-16). Дополняет [0010](0010-frontend-own-client.md) (стек React + React Flow остаётся).

## Контекст
Фронт вырос в «всё в одном файле»: `SystemView.tsx` ~1860 строк, ~50 файлов плоско в `src/`. Новые экраны из макета (Старт, Обзор, Проблема, Влияние, Карта, Срезы, Дифф, Отчёт, Состояния) так строить нельзя: непроверяемо, нечитаемо, ревью не масштабируется. Имена сервисов и типов приходят из чужих репозиториев, поэтому разметка из данных — риск XSS.

## Решение
- **Структура `frontend/src/`:** `app/` (провайдеры, роутер, оболочка), `features/<экран>/` (одна папка — один экран), `shared/{ui,api,lib,styles}`, `legacy/` (старый код), `test/` (хелперы тестов).
- **Роутер:** `react-router` (библиотечный режим, `createBrowserRouter`, маршруты с `lazy`). У каждого экрана свой URL: `/`, `/overview`, `/problems/:id`, `/impact/:node`, `/map`, `/slices`, `/diff`, `/report`, `/states`. Оболочка (верхняя панель, навигация), 404 и error boundary маршрута — в `app/`.
- **Данные:** TanStack Query (`staleTime` 60 с, без refetch по фокусу окна, 4xx не повторяем) поверх тонкого `shared/api/client.ts` (fetch, отмена через `AbortSignal`, таймаут, `ApiError`). Базовый URL `/api` — Vite-прокси на `Map`, как раньше.
- **Типы ответов — вручную** (`shared/api/types.ts`, по `backend/shared/ArchForge.Contracts`): бэк не отдаёт OpenAPI. **Долг:** когда появится OpenAPI-документ, добавить `npm run api:types` (генерация) и удалить ручные типы.
- **Стили:** CSS Modules + токены в `shared/styles/tokens.css` (цвета, отступы, радиусы, типографика; светлая/тёмная тема через `prefers-color-scheme` и `data-theme`). Палитра — из макета, статусы: ошибка / предупреждение / ок / неизвестно.
- **Границы проверяет `npm run lint`:** `oxlint` — `max-lines` 300 в `app/features/shared` и `react/no-danger`; `scripts/check-boundaries.mjs` — запрет импорта между `features/*`, запрет импорта `legacy/` вне `features/map/legacy-adapter.tsx`, направление слоёв (`shared` ← `features` ← `app`; `legacy` не знает про новый код).
- **`legacy/`:** весь прежний код перенесён механически (`git mv`, ноль изменений логики; тесты — вместе с файлами). **Правило: заморожен, новых фич нет, разбираем по частям в `features/map`, удаляем, когда пуст.** Единственный мост — `features/map/legacy-adapter.tsx`, монтирует `SystemView`. Глобальные стили старой карты (`legacy/index.css`) ограничены корнем `.legacy-root`, чтобы не влиять на новые экраны; лимит длины файла для `legacy/` отключён (там долг).

## Альтернативы
- **Постепенная правка на месте, без `legacy/`.** Отклонено: новый и старый код смешиваются, правила границ не проверить механически.
- **Next.js / Remix (framework mode).** Отклонено: SSR не нужен, локальное приложение с Vite-прокси; хватает библиотечного режима.
- **Redux / Zustand для серверных данных.** Отклонено: кэш, отмена и повторы — задача TanStack Query.
- **Tailwind.** Отклонено: нужны токены тем и изоляция стилей на уровне компонента; CSS Modules проще и без новой зависимости сборки.
- **Один `no-restricted-imports` в oxlint вместо скрипта.** Не покрывает «экран не импортирует другой экран» без перечисления пар; скрипт короче и точнее.

## Последствия
- Новые экраны делаются отдельными PR по одному на папку `features/<экран>`; заглушки показывают «Экран ещё не сделан».
- Основной бандл не тянет карту: `/map` грузит `legacy/` (react-flow, elk) лениво.
- Старая карта по-прежнему на тёмной теме и вне токенов; перенос на токены — часть её разбора.
- Ручные типы API могут разойтись с контрактом бэка, пока нет OpenAPI (долг выше).
