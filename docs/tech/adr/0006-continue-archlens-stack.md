# 0006 — arch_forge продолжает archlens (стек Node/TS + tree-sitter + React Flow)

## Статус
Заменён на [0009](0009-dotnet-roslyn-microservices.md) (2026-08-14): разворот в Node/TS был ошибочным — возвращаемся на .NET + Roslyn по своду. Ниже — исходный (неактуальный) текст.

Исходно: Принято. Заменял [0002](0002-local-web-app.md) и [0003](0003-roslyn-analysis-engine.md).

## Контекст
В ходе проработки выяснилось: существует рабочий прототип `archlens` (репо KalmykovGroup-HowToUseIt), реализующий ту же идею и уже дальше нас — авто-схема сервисов и слоёв на живых данных, IR-модель, React Flow клиент, локальный агент, tree-sitter для полиглота. Ранние ADR 0002 (.NET-бэкенд) и 0003 (Roslyn как движок) исходили из greenfield и противоречат реальности archlens.

## Решение
- **Продолжать archlens, а не переписывать.** Фундамент здоровый; наш вклад — глубина (тип-уровень, convention-pack, линт) и доводка до продукта.
- **Стек = стек archlens:** Node/TS монорепо, **tree-sitter** для полиглот-разбора, манифест/`.csproj`/lock-экстракторы, **React Flow** клиент, Node-сервер (API), локальный агент.
- **Roslyn — опциональный precision-слой для .NET-семантики** (тип-уровень, точные роли по маркерам) на собираемых проектах, а не основной движок.
- Реализация ведётся в репозитории archlens; этот `arch_forge`-репозиторий держит вижен/план.

## Альтернативы
- **Greenfield .NET + Roslyn (наши 0002/0003).** Отклонено: повторное изобретение того, что archlens уже делает полиглотно; выбрасывает рабочий фундамент.
- **Начать заново на другом стеке.** Отклонено по той же причине.

## Последствия
- Ближайшая работа — довести archlens до DoD Фазы 1 (`ROADMAP.md`, `docs/tech/archive/plan-phase-1.md`), а не строить с нуля.
- **Открытый организационный вопрос:** где живёт код и как соотносятся репозитории arch_forge и archlens (свести / переименовать). Решить отдельно.
- .NET перестаёт быть «языком бэкенда продукта»; он — один из целевых языков анализа (первый реализованный провайдер).
