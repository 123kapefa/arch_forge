Довести `archlens` до DoD Фазы 1 (`VISION.md`). Каждый пункт — сквозной проверяемый срез. Порядок: риск-первым (прототипы P0).

## Граф зависимостей
`P0 → P1-1 → P1-2 → {P1-3→P1-5}·{P1-4→P1-5} → P1-6`; `P1-7` — сквозной.

## P0 — Прототипы риска (снять неопределённость, без UI)
- **P0-a Convention-pack на .NET:** Roslyn по типу достаёт базовые типы/интерфейсы/атрибуты → роль по паку; на `auth_service` выдать роли + отклонения в JSON.
- **P0-b Тип-граф:** по одному слою (Domain/Core) вытащить типы + рёбра `holds/implements/raises` в JSON.
- Готово: JSON верен на реальном сервисе; понятно, что и как извлекается.

### P0 — результат (2026-08-14, проверено на `auth_service`)
- ✅ Классификация ролей по паку: unknown 87% → **6%** после обогащения пака (Identity/EF/OpenIddict/Razor/порт-адаптеры/DTO/Options).
- ✅ Дрейф от свода: 4 находки (`RegisterAccountCommand/Handler` без маркеров, `SecurityAuditEvent` не `IDomainEvent`, `ClientCredentialsTokenHandler`). Маркеры свода — 0% (сервис их не использует).
- ✅ Тип-граф: `implements` (порт↔адаптер) и `holds` извлекаются; нужен ещё вид ребра `uses` (конструкторы/методы) для плотности.
- ⚠️ Семантика через MSBuildWorkspace на строгом билде цели не поднялась (см. `adr/0008`) → синтаксический пол + пак; семантика оппортунистически.
- Спайк (`archforge-spike`) — семя .NET precision-провайдера для P1-3/P1-4.

- Цель: не падать на большом/битом/чужом репо.
