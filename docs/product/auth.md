# Вход и сессия

Вход в arch_forge идёт через сервер входа по стандарту OIDC (например, `auth_service` на Keycloak). Приложение не хранит паролей. Пока вход не блокирует функции; проверка права на использование включается настройкой.

## Что видит пользователь
В шапке карты — кнопка со статусом входа:
| Статус | Что означает |
|---|---|
| имя пользователя | вход выполнен |
| «имя · без связи» | нет связи с сервером входа, работаем по сохранённой сессии; в окне показаны остаток автономного срока и дата |
| жёлтая кнопка | до конца автономного срока осталось 3 дня или меньше; можно войти заново |
| «Нужен вход» | срок вышел или часы компьютера сдвинуты назад |
| «Войти» | вход не выполнен |
| «Режим разработки» | вход отключён, запросы идут от тестового пользователя (только для разработки) |

Окно по клику показывает подробности и кнопки «Войти», «Выйти», «Обновить». После возврата с сервера входа показывается результат («Вход выполнен» или «Войти не удалось»). Статус обновляется раз в минуту.

## Как устроен вход
- Вход через браузер: код авторизации + PKCE (S256), публичный клиент (по умолчанию `archforge-desktop`).
- Владелец сессии — сервис **Map**. Токены хранятся на диске в зашифрованном файле `session.bin` (AES-256-GCM); ключ защищён системой: DPAPI (Windows), Keychain (macOS), иначе файл `session.key` с доступом только владельцу. Способ хранения виден в статусе сессии.
- Токены в интерфейс не передаются: фронт получает только статус.
- Токен доступа обновляется в фоне; если сервер отозвал доступ, сессия стирается.
- **Автономная работа:** до 14 дней от последнего успешного обмена с сервером входа, предупреждение за 3 дня. Потом нужен новый вход. Откат часов назад больше чем на 5 минут тоже требует входа.
- Вход привязан к браузеру, который его начал (cookie `archforge_login`); адрес возврата задан настройкой, а не берётся из запроса.
- Запросы с этой же машины без заголовка `Authorization` идут как вошедший пользователь по локальной сессии, но только если это не запрос с чужого сайта.
- **Analysis** закрыт от прямых обращений: принимает только запросы с loopback и (вне разработки) с общим ключом `Internal:Key`, который Map добавляет сам.

## Права
В токене сервера входа приходят роль (`role`) и права (`permissions`). Для arch_forge определено право **`archforge.use`** и роль по умолчанию `user`, которая его даёт. При `Authentication:RequireLogin=true` всё API требует вошедшего с этим правом: без входа ответ 401, без права 403. `GET /api/me` показывает субъект, роли и права.

## Режимы работы
1. **Сервер входа.** Заданы `Authentication:Authority` и `Authentication:Audience`: токены проверяются (подпись RS256, издатель, адресат, срок).
2. **Режим разработки.** `Authentication:DevMode=true` — только в окружении `Development` и не вместе с `Authority`.
3. Иначе приложение не стартует.

## Настройки
| Ключ | Назначение |
|---|---|
| `Authentication:Authority`, `Audience` | сервер входа и адресат токенов (для `auth_service` — код приложения, `archforge`) |
| `Authentication:InternalAuthority` | адрес сервера входа изнутри сети (https) |
| `Authentication:AllowInsecureMetadata` | http для сервера входа, только в `Development` |
| `Authentication:DevMode` | режим разработки |
| `Authentication:RequireLogin` | закрыть всё API для невошедших и без права `archforge.use` |
| `Auth:ClientId`, `Scope` | клиент OIDC (`archforge-desktop`, `openid`) |
| `Auth:RedirectBaseUrl`, `FrontendUrl` | адрес Map для возврата из браузера (`http://localhost:5200`) и страница приложения (`http://localhost:5173/`) |
| `Auth:Directory` | папка данных сессии (по умолчанию — папка данных пользователя) |
| `Auth:AllowLocalSession` | локальная сессия для запросов без токена (отключайте за прокси и в сети) |
| `Auth:GraceDays`, `WarnDays`, `ClockToleranceMinutes` | 14, 3 и 5 по умолчанию |
| `Internal:Key` | общий ключ Map → Analysis (16–256 печатных ASCII-символов; обязателен вне `Development`) |

В Keycloak у клиента входа должен быть redirect URI `{Auth:RedirectBaseUrl}/api/auth/callback`.

Если Map доступен не только с вашей машины или стоит за прокси на ней самой, включите `Authentication:RequireLogin=true` и `Auth:AllowLocalSession=false`: тогда принимаются только запросы с токеном.
