# Профили проекта

Профиль определяет, какие правила проверяются и насколько строго. Один и тот же код может быть нормой для маленького проекта и нарушением для большой платформы, поэтому правила настраиваются.

## Уровни
| Уровень | Для чего |
|---|---|
| **Simple** | небольшой проект: мягкие «свод-правила» (маркерные интерфейсы, маппинг DTO) выключены |
| **Standard** | уровень по умолчанию |
| **Platform** | полный свод платформы |

Строгость правил, которых уровень не задаёт, определяет сам детектор (родная серьёзность). Выбранный уровень подсказывается по признакам проекта (число сервисов, брокер, маркерные интерфейсы), но не навязывается.

## Окно «Профиль проекта»
Три вкладки:
1. **Правила.** Для каждого правила каталога: строгость `Off` / `Info` / `Warning` / `Error`, пример «плохо / хорошо», параметры (порог уверенности циклов между сервисами, минимум мест и файлов для `dto-mapping`). Правило, изменённое относительно уровня, помечено; сбросить можно правило, категорию или весь профиль. Рядом с правилом видно, сколько находок оно даёт на открытом проекте (предпросмотр влияния).
2. **Словарь.** Как называются вещи в коде проекта: для каждой роли (команда, запрос, хендлер, валидатор, endpoint, агрегат, событие…) — маркерные интерфейсы, запасные маркеры и суффиксы имён; суффиксы имён сервисов, миграций и сателлитов в compose.
3. **Свои правила.** Конструктор из шаблонов, без кода (см. ниже).

## Свои правила
Шаблоны:
- **suffix-base** — тип с суффиксом наследует заданный базовый тип;
- **layer-no-ref** — один слой не ссылается на другой;
- **forbid-in-folder** — запретить тип в папке;
- **role-in-folder** — роль должна лежать в определённой папке.

Находка называется `custom:<id>`. Папки считаются от корня сервиса, типы слоя `tests` не оцениваются. Лимиты: до 32 правил, поля до 64 символов, не более 1000 перечисленных элементов в одной находке, профиль не больше 64 КБ. Регулярные выражения не поддерживаются. Сохранить профиль с незаполненным правилом нельзя.

## Конфигурации
Профиль можно сохранить как именованную **конфигурацию**: создать, переименовать, дублировать, удалить, привязать к проекту. Конфигурация хранит базовый уровень, версию каталога правил и только отличия от уровня; это манифест, который можно экспортировать в файл и импортировать из файла или вставкой JSON. Проект разбирается по привязанной к нему конфигурации.

## Файл в разбираемом проекте
Правила свода по-прежнему можно дополнить файлом `archforge.conventions.json` (или `.archforge/conventions.json`) в корне разбираемого проекта.
