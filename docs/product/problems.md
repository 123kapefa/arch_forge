# Проблемы и правила

Анализатор ищет проблемы архитектуры и расхождения с правилами проекта. Каждая находка несёт идентификатор правила, серьёзность (`Info` / `Warning` / `Error`) и источник.

## Каталог правил
| Идентификатор | Категория | Что находит |
|---|---|---|
| `shared-db` | архитектура | общая БД у нескольких сервисов |
| `shared-store` | архитектура | общее хранилище (например, Redis) у нескольких сервисов |
| `service-cycle` | архитектура | циклы между сервисами (учитывается уверенность связи) |
| `dangling-event` | архитектура | событие публикуется, подписчика нет |
| `orphaned-subscription` | архитектура | есть подписка, издателя нет |
| `exposed-datastore` | архитектура | порт хранилища опубликован наружу |
| `layer-violation` | архитектура | нарушено направление зависимостей слоёв Clean Architecture |
| `drift` | свод | тип не соответствует правилам роли (например, хендлер без маркерного интерфейса) |
| `dto-mapping` | свод | DTO собирается инлайн в нескольких местах вместо маппера |
| `custom:<id>` | свод | ваши [свои правила](profiles.md#свои-правила) |

Строгость каждого правила и параметры (порог уверенности циклов, минимум мест для `dto-mapping`) задаются в [профиле проекта](profiles.md). Выключенное правило остаётся видимым в сводке как выключенное.

## Здоровье
Каждый узел (система, сервис, слой) получает цветовой показатель по числу и серьёзности проблем внутри: он подсказывает, куда проваливаться.

## Покрытие
Тип классифицируется тремя способами: по **маркеру** (точно), по **эвристике** (по имени, например суффикс `Handler`) или остаётся **unknown**. Доли показываются честно; неоднозначное не выдумывается.

## Деградация
Если часть проекта не разобрана (нет `bin/`, файл слишком большой, ошибка разбора), это помечается явно, а остальное всё равно показывается.
