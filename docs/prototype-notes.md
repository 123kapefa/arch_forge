# arch_forge — прототип «картина системы»: рабочие заметки

**Статус:** рабочий документ к интерактивному прототипу. Не ADR.
Это единый источник правды по тому, **что** заложено в прототип и **зачем** — чтобы позже разложить на эпики/задачи, не вытаскивая всё «из головы» и не реверс-инжиниря сам прототип.

**Прототип (Artifact):** https://claude.ai/code/artifact/423df812-9a11-438a-a032-4b0b4fcd3442
**Реальный код UI, с которого снят каркас:** `frontend/src/SystemView.tsx`, `frontend/src/system.css`.

---

## 1. Замысел

Один экран — **вся микросервисная система**. Три цели:
1. **Понять большую систему** (десятки сервисов, чужой код).
2. **Найти кросс-сервисные проблемы** (арх-ревью).
3. **Видеть DevOps-картину по окружениям** (dev/stage/prod: порты, сети, зависимости).

«Код как плашка» (Фаза 1) — вторично; это подложка, а не цель.

> **Важно (чтобы ничего не потерялось).** Прототип — это **не замена** текущего приложения, а **тот же React Flow-борд + новые линзы и уровни поверх него**. Ничего из уже реализованного не выбрасывается. Прототип намеренно на **4 сервисах** (для наглядности) — на реальной доске (15+ сервисов, `*-migrations`, `postgres-*`, `$CONFIG`-узлы, внешние моки, инфра-строка) действует та же модель.

### Куда что ложится (новое → текущее приложение)

| Новое в прототипе | Где живёт в реальном приложении |
|---|---|
| Виды **Deploy / Поток / Сравнение сред** | новые **линзы уровня System (L0)** рядом со Структурой |
| **Области** (папки / docker-сети) | оверлей-группировка поверх того же L0-борда |
| **Провенанс** (источник / уверенность / почему) | обогащение инспектора факта (пути к файлу уже есть) + подписи на рёбрах |
| **Данные на стрелке** (конвертации вход/выход) | деталь внутри вида Поток |
| **DI** | **уровень сервиса (L1)**, рядом с endpoints и слоями |
| **Оценки** | агрегат-бейджи в топбаре / инспекторе |
| **L0 / L1 / L2 drill** | это **уже есть** в приложении — прототип теперь его повторяет |

**Разрыв прототипа с реальностью — частично закрыт:** L0 переведён на реальный масштаб (**11 сервисов + `postgres-*` + `*-migrations` кластерами + инфра-строка**, авто-раскладка, зоны `src/Services/*`). Остаётся: полная ELK-раскладка, миникарта, пан/зум, узлы `$CONFIG`/внешние моки — это в реальном приложении. Модель идентична; отличается объём данных и движок раскладки.

## 2. Модель навигации (две ортогональные оси)

- **Масштаб** (крошки): `System ▸ Service ▸ Layer ▸ Type ▸ Member` — *где* ты находишься.
- **Вид/линза** — *что* ты смотришь на этом уровне.

| Уровень | Виды на этом уровне |
|---|---|
| **System (L0)** | Структура · Deploy · Поток · Сравнение сред |
| **Service (L1)** | Слои · Endpoints · **DI** |
| **Layer (L2)** | Типы · дрейф от свода |
| **Type / Member** | члены типа |

**Зафиксированные решения (подтверждены пользователем):**
- **Поток = системный уровень**, но навигация деревом **сервис → endpoint** (кросс-сервисный трейс, вход — endpoint конкретного сервиса).
- **DI = уровень сервиса** (у каждого свой контейнер), открывается при выборе сервиса; не системная вкладка.

## 3. Соответствие статическому анализу (осуществимость)

| Что показываем | Откуда берётся | Достоверность |
|---|---|---|
| Сервисы + слои + типы | Roslyn (семантика) | высокая |
| Связи http-call | Roslyn: `HttpClient`/типизированные клиенты | высокая/средняя |
| Связи rw-db | Roslyn: `DbContext`/репозитории | высокая |
| Связи uses-bus / события | Roslyn: publish/subscribe API шины | средняя |
| Endpoints (route, verb, тип запроса/ответа) | Roslyn: контроллеры + minimal API | высокая |
| Конвертации данных (вход/выход, JSON↔класс) | Roslyn: сигнатуры методов, (де)сериализация, мапперы | средняя |
| Порты / сети / healthcheck / depends_on | парсинг compose (+ env-оверрайды) | высокая |
| Env-диффы (dev/stage/prod) | compose override-файлы | высокая |
| DI (регистрации, времена жизни, captive) | Roslyn: `AddSingleton/Scoped/Transient` | высокая |
| Поток целиком (последовательность) | статич. call-graph от endpoint | **частично** — happy-path; без рантайма |
| Циклы, общая БД, длинные синхронные пути | граф связей | высокая |
| Разрыв контракта (потеря поля) | диф типов вход/выход по цепочке | средняя |
| Секреты/значения env | **не значения**, только *наличие ключей* | — |

Общий принцип: показываем **контракт/структуру**, а не рантайм-значения. Всё, что помечено «частично», требует честной пометки в UI («без рантайма»).

## 4. Реализовано в прототипе

> Легенда статуса: ✅ в макете · 🟡 частично · ⛳ запланировано.

| R7 | **Инспектор узла** | Имя, вид, СЛОИ (число типов), проблемы (линза), СВЯЗИ (→/←), Deploy-блок | Roslyn + граф | ✅ |
| R8 | **Поток**: список сценариев | Дерево **сервис → endpoint** (verb-бейджи), фильтр, сворачивание сервисов | контроллеры/minimal API | ✅ |
| R9 | **Поток**: диаграмма | Sequence по выбранному endpoint; типы стрелок (вызов/ответ/событие/внешний); шапка «вход/участники»; на всю ширину | статич. call-graph | 🟡 (happy-path) |
| R10 | **Поток**: данные на стрелке | Формат + схема + **конвертация вход→выход** (JSON↔класс) в инспекторе | сигнатуры/сериализация | ✅ |
| R11 | **DI** (уровень сервиса) | Регистрации, времена жизни, **captive dependency**, незарег. зависимость | `Add*` в контейнере | ✅ |
| R12 | **Оценки** и **линза** | Оценка архитектуры/среды; линза «реальные проблемы» / «дрейф от свода» | агрегат находок | 🟡 (оценка — заглушка-агрегат) |
| R13 | Панели | Сворачивание левой/правой панели; раскрывающийся drawer проблем; крошки по уровню | — | ✅ |
| R14 | **Уровни L0→L1→L2 (drill)** | Двойной клик по сервису → его слои (L1); по слою → типы (L2); клик по типу → члены; крошки навигируют вверх. **Endpoints и DI живут на L1.** L1-карточки как в реальном приложении: превью типов (первые 6 + «ещё N»), бейдж дрейфа («N без роли» / «N расхождений со сводом»), цветная граница слоя, **рёбра зависимостей между слоями** (Clean Arch) | Roslyn (семантика) | ✅ |
| R15 | **L0 в реальном масштабе** | 11 сервисов + `postgres-*` + `*-migrations` + `postgres-*-export` + `$*_DB_URL` кластерами + инфра-строка, авто-раскладка, зоны `src/Services/*`, **ортогональная разводка рёбер** (прямые углы). Deploy/Поток/DI/провенанс поверх | compose + Roslyn | ✅ |
| R16 | **Фильтр повторяющихся блоков** | Система авто-детектит однотипные узлы, повторяющиеся у каждого сервиса (по имени): `*-migrations`, `postgres-*`, `*-export`, `$*` конфиги, инфра. Тумблеры «ПОВТОРЯЮЩИЕСЯ БЛОКИ» **скрывают** (не удаляют) категорию целиком; экспортеры/конфиги скрыты по умолчанию для чистоты. Скрытие убирает и узлы, и их рёбра, и сжимает зоны. Блоки привязаны к сервису-владельцу (`owner`) → все в одной зоне `src/Services/<svc>` | имя/паттерн узла | ✅ |
| R17 | **Клик по ребру → инспектор связи** | Каждое ребро кликабельно (hit-полоса). Клик → в инспекторе: направление, вид (HTTP/БД/шина), и **что идёт по связи**: для http-call — список запросов (напр. `api-gateway → orders-api`: POST /orders, /pay, /cancel…), для rw-db — операции (SELECT/INSERT/UPDATE таблиц), для шины — публикуемые/потребляемые события; плюс источник и уверенность. HTTP-запросы gateway→сервис выводятся из endpoint'ов сервиса | Roslyn (call-graph, endpoints) | ✅ |
| R18 | **Единый инспектор + связность** | Любой выбор (узел / связь / находка / слой / тип / шаг потока / DI / сравнение) рендерится по одной структуре: **метка «что это»** (УЗЕЛ / СВЯЗЬ / НАХОДКА / …) + заголовок + подзаголовок + секции. Функции связаны: в узле связи кликабельны → открывают инспектор связи; из инспектора связи виден провенанс → «открыть в коде». Единое пустое состояние | — | ✅ |

## 5. Запланировано — приоритетный бэклог (кандидаты в эпики)

> Порядок = приоритет. Первые три — ядро; без них тул = «красивая картинка».

### P1. Провенанс / доверие ✅ (в макете)
На каждом ребре / находке / конвертации — **источник** (`файл:строка`), **уверенность** (цветной чип hi/mid/lo), **«почему»** (доказательство: какой вызов/атрибут), и кнопка → **переход в код** (заглушка).
- **Ценность:** для статич. анализатора это главное — без «откуда вывод» карте не верят.
- **Реально:** да, Roslyn знает location каждого символа; уверенность = маркер vs эвристика.
- **Реализовано в прототипе на 3 поверхностях:**
  - **Находки** — клик по строке в drawer «ПРОБЛЕМЫ ПРОЕКТА» → в инспекторе источник + уверенность + «почему» + «открыть в коде / показать плашку». В drawer источник вынесен в колонку.
  - **Связи** — в блоке СВЯЗИ инспектора узла каждое ребро подписано `файл:строка` + уверенность.
  - **Конвертации** — в панели данных стрелки Потока (вход/выход) — «источник конвертации · доверие».
- **Осталось для реального модуля:** настоящий переход в код (сейчас кнопка-заглушка); порог по уверенности как фильтр (в реальном UI есть ползунок).

### P2. Экран-обзор (триаж) ⛳
Стартовый экран на большую систему: худшие сервисы по оценке, топ кросс-сервисных проблем, покрытие анализа, «что не разобралось». Сначала «где болит» — потом карта.
- **Ценность:** ориентация при масштабе (50 сервисов).

### P3. Каталог кросс-сервисных детекторов 🟡 (есть бар проблем)
Проблемы как **навигируемый каталог с переходом**, а не только бейджи: циклы (A→B→A), общая БД (кто пишет), самый длинный синхронный путь, **разрыв контракта** (потеря поля / версии `/v1`↔`/v2`).
- **Ценность:** это и есть payoff «арх-ревью».

### P4. Поиск и фокус ⛳
`⌘K`-переход к любому сервису/типу/endpoint; режим «только соседи X» (изолировать окрестность).
- **Ценность:** читаемость при десятках сервисов.

### P5. Диффы ⛳ (env-дифф уже есть)
- **Во времени / между коммитами:** «появился новый цикл», «сервис получил доступ к чужой БД» — регрессии архитектуры.
- **Против целевой архитектуры:** правила свода как явные инварианты («запрещено: X → БД Y напрямую»), не только мягкий дрейф.

### P6. Конфиг/секреты и границы доступа per env ⛳
Какие env-переменные / connection strings нужны сервису и **чего не хватает в prod**; публичные endpoint'ы без auth; TLS/CORS. (Значения секретов не показываем — только наличие ключей.)
- **Ценность:** завершает DevOps-картину (порты уже есть).

### P7. Глубина Потока ⛳
Пути ошибок (таймаут/ретрай/fallback); кто **потребляет событие** (подписчики `OrderCreated`); auth на каждом хопе.

### P8. Отчёт-ревью ⛳
Выгружаемый отчёт (MD/PDF) по результатам арх-ревью + постоянные ссылки на конкретную находку (поделиться с коллегой). Сейчас экспорт только JSON.
