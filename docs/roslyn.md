# Roslyn — движок анализа C#

Reference по библиотеке, на которой стоит сервис `Analysis`: зачем она, как работает, где границы.

## Что это

Roslyn (`Microsoft.CodeAnalysis`) — официальный компилятор C#/VB от Microsoft, доступный **как библиотека**. Тот же движок, что компилирует код и даёт IntelliSense/рефакторинги в Rider/VS. Мы вызываем его сами и читаем, что он «понял» про код — точно как компилятор.

## Зачем нам

Мы статически разбираем чужой C#. Понять код правильно можно только как компилятор — не регекспами (регекс ломается, напр. на первичных конструкторах C# 12). Roslyn даёт точный разбор + понимание смысла (типы, наследование, ссылки).

## Два уровня

### 1. Синтаксис (Syntax Tree) — «пол»
Парсинг текста `.cs` в дерево (классы, методы, базовый список, дженерики, атрибуты). Только **структура**: видит строку «`IdentityDbContext`», но не знает, что это. Быстро, на одном файле, даже на битом/несобираемом коде. Резильентно → используется как пол (`adr/0008`). API: `CSharpSyntaxTree.ParseText`.

### 2. Семантика (Compilation + Symbols) — точность
Все файлы **+ ссылки на сборки** → `Compilation` (вся программа понята целиком). У каждого типа — символ (`INamedTypeSymbol`) с разрешёнными `BaseType`, `AllInterfaces`, членами, атрибутами, неймспейсом. `SemanticModel` отвечает «что значит этот идентификатор». Требует, чтобы проект собирался (нужны референсы) — потому `Analysis` тяжёлый и отдельный.

## Разница на примере

`class AuthDbContext : IdentityDbContext<Account, Role, Guid>`
- **Синтаксис:** база = `IdentityDbContext` (просто имя).
- **Семантика:** по цепочке наследования знает, что это `DbContext` (EF Core) → правильная роль. Регекс/синтаксис так не могут.

`RegisterAccountHandler(UserManager<Account> m, ISecurityAuditWriter w)` — семантика резолвит `Account`/`ISecurityAuditWriter` в реальные типы → точные `uses`-рёбра, и знает, что `Account` — свой тип из Domain.

## Пайплайн (сервис Analysis)

`MSBuildWorkspace` (читает `.sln/.csproj` + референсы) → `Compilation` на проект → обход символов типов → классификация ролей по convention-pack + тип-граф + линт → IR (контракт `ArchForge.Contracts`).

Если проект не собирается (строгий билд — напр. `TreatWarningsAsErrors` + NuGet-audit `NU1903` у `auth_service`) → падаем на синтаксический пол.

## Границы и бонусы

- Roslyn **не запускает** код — понимает статически (read-only).
- Он умеет и **переписывать** код (генерация/рефакторинг) — пригодится в Фазе 2 (ИИ-правки применяются точными операциями Roslyn, а не текстом).
- Наш линт (дрейф, направление слоёв) можно упаковать в **Roslyn-анализатор** → подсветка прямо в IDE и в CI (Фаза 3).

## Ключевые типы

`SyntaxTree` (дерево одного файла) · `Compilation` (вся программа) · `INamedTypeSymbol`/`ISymbol` (разрешённый элемент) · `SemanticModel` (синтаксис → символ) · `MSBuildWorkspace` (загрузка реального solution с референсами).
