# 0005 — ИИ-доработка через провайдер-адаптер (направление Фазы 2)

## Статус
Предложено (направление Фазы 2, не реализуется в Фазе 1).

## Контекст
Вторая часть продукта — правка кода через ИИ прямо с карты. Хотим: (а) не платить за чужие токены и не хранить секретов, (б) дать пользователю использовать то, что у него уже есть (Claude Code, Codex, локальная модель), (в) не закрыть путь к собственному облачному шлюзу позже.

## Решение
Ввести абстракцию **`IAgentRunner`** и адаптеры:

- **Claude CLI** — headless-вызов (напр. `claude -p "<инструкция>"` в рабочей папке; позже возможен Claude Agent SDK для структурных событий).
- **Codex CLI** — неинтерактивный режим.
- **Локальная модель** — Ollama/OpenAI-совместимый HTTP.
- **Кастомный шаблон команды** — с плейсхолдерами (`{repo}`, `{prompt}`), чтобы подключить что угодно.

Поток: карта собирает контекст-бандл по выбранной плашке (код + правила слоёв + инструкция) → адаптер запускает провайдера в рабочей папке → правки на месте → **diff на апрув** → ре-анализ карты. Приложение агностично к подписке: авторизацию держит сам CLI пользователя.

## Альтернативы
- **Свой облачный ИИ-шлюз сразу.** Отложено: несём токен-косты и inference; оставлено как ещё один адаптер позже (тогда же — метеринг/монетизация).
- **Жёсткая привязка к одному провайдеру.** Отклонено: теряется BYO-гибкость.

## Последствия
- Монетизация чистая: инструмент — по подписке-лицензии, ИИ — на стороне пользователя (BYO).
- Требует от Фазы 1 стабильных якорей на исходник (для контекст-бандлов) — уже заложено.
- Нюансы к решению позже: permission-posture для headless-правок; целевой проект как git-репозиторий для diff; безопасная сборка команды (аргументами, не склейкой строк в shell).
