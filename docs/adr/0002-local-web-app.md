# 0002 — Локальное веб-приложение (.NET + React/React Flow)

## Статус
Заменён на [0006](0006-continue-archlens-stack.md) (2026-08-14): arch_forge продолжает archlens (Node/TS + tree-sitter + React Flow), а не greenfield .NET. Ниже — исходное решение (для истории).

Исходно: Принято.

## Контекст
Инструмент должен разбирать локальный C#/.NET-код и рисовать «блюпринт»-граф. Движок разбора обязан быть на .NET (Roslyn/MSBuildWorkspace — см. ADR-0003), а лучшие узловые графы — в вебе (React Flow). Пользователь хочет работать локально; проприетарный код не должен уходить в облако. Рассматривали также десктоп и полный SaaS.

## Решение
MVP и старт — **локальное веб-приложение**: `.NET`-бэкенд (движок + HTTP API) + React/React Flow фронт, поднимается на `localhost`. Целевой код читается на машине пользователя и наружу не уходит.

Закладываем **гарды совместимости с будущим десктопом** (стоят дёшево):

1. Чистый раздел фронт/бэк по HTTP (не монолит с жёсткой связкой).
2. Конфигурируемые base URL и порт (не захардкожены).
3. Бэкенд — самодостаточный процесс (`dotnet publish` self-contained), спавнится как сайдкар.
4. Доступ к файловой системе — только в бэкенде.

## Альтернативы
- **Десктоп-первым (Tauri/Electron + .NET-сайдкар).** Отклонено как старт: плата за упаковку (сборка, подпись, авто-апдейт, менеджмент процесса) без выгоды на MVP. Оставлено как опциональный поздний слой.
- **Чистый .NET-десктоп (Avalonia/MAUI).** Отклонено: теряется React Flow, зрелых блюпринт-графов в .NET меньше.
- **Полный SaaS (анализ в облаке).** Отклонено как основной: проприетарный C# не должен покидать периметр; мы несём compute.

## Последствия
- Совпадает со стеком репозитория (.NET + React).
- Десктоп остаётся достижим одним слоем упаковки, без рефакторинга (Tauri предпочтительнее Electron: системный webview, единицы МБ).
- UX старта — «подними локальный сервер → открой браузер».
