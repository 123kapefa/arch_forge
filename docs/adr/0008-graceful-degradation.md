# 0008 — Graceful degradation и честность покрытия

## Статус
Принято (2026-08-14).

## Контекст
Цель — разбирать **чужие** проекты, включая плохо структурированные. Нельзя требовать соблюдения конвенций. Граница разбираемости — «исходники или нет», а не «хорошо или плохо»: плохая архитектура — это **продукт** (находки), а не препятствие.

## Решение
**Градуированная деградация — всегда отдаём результат, никогда не врём:**
- **Пол (всегда):** проекты, `ProjectReference`, сервисы и их связи — из механики MSBuild/манифестов/парсера; работает даже на несобираемом коде (tree-sitter).
- **Средний:** роли по встроенному паку / эвристикам на обычных проектах.
- **Верх:** точные роли + линт на проектах с convention-pack (`adr/0007`).
- **Честность:** неоднозначное → `unknown` (не выдумываем) + **отчёт покрытия** (сколько по маркерам / эвристике / unknown).

Требования к реализации: изоляция ошибок по файлам, исключение `bin/obj/generated`, укрощение масштаба (группировка/collapse/focus), таймауты.

## Альтернативы
- **Требовать сборку/конвенции.** Отклонено: убивает исходную цель (чужие проекты).
- **Догадываться молча.** Отклонено: ложная уверенность хуже честного `unknown`.

## Последствия
- Глубокая .NET-семантика требует сборки (Roslyn); ниже — tree-sitter-структура.
- Покрытие/уверенность — часть UI (бейдж): пользователь знает, насколько верить карте.
- Проверено прототипом (2026-08-14): MSBuildWorkspace на строгом чужом проекте (`TreatWarningsAsErrors` + NuGet-audit `NU1903` как ошибка) не поднимает design-time build, глобальные свойства его не переопределяют. Вывод: семантику брать оппортунистически; синтаксический разбор + богатый пак — пол (на `auth_service` дали 94% покрытия).
