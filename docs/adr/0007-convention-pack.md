# 0007 — Convention-pack: классификация ролей и линт дрейфа

## Статус
Принято (2026-08-14).

## Контекст
Роли классов (команда/валидатор/эндпоинт/хендлер/агрегат/VO/событие/порт…) точнее всего определяются не по именам/папкам, а по **маркерам** — базовым типам, интерфейсам, атрибутам. Команды, документирующие конвенции (напр. свод в Obsidian: `ICommand`, `IEndpoint`, `ICommandHandler<>`, `AbstractValidator<>`, `: Aggregate`, `IDomainEvent`, «вертикальный срез»), дают идеальный источник правил.

## Решение
Ввести **convention-pack** — формализованный набор правил: `маркер → стереотип`, ожидаемый состав среза, направление зависимостей слоёв.
- Движок извлекает по каждому типу базовые типы/интерфейсы/атрибуты и матчит с паком → **роль**.
- Несовпадение с ожидаемым паттерном → **отклонение (drift)**: элемент линта против документированной архитектуры.
- Паки: **встроенный дефолт** (популярные .NET-паттерны — MediatR/FluentValidation/ASP.NET/EF) + **пользовательский** (импорт из свода команды).

Проверено на `auth_service`: срез `RegisterAccount` расходится со сводом (нет `ICommand`/`ICommandHandler`/`IEndpoint`, валидация inline, `Account : IdentityUser` вместо `Aggregate`) — инструмент это выявляет.

## Альтернативы
- **Эвристики по именам/папкам.** Оставлены как fallback (см. `adr/0008`), но менее точны и не дают линта.
- **Без паков (только структура).** Теряется главный дифференциатор.

## Последствия
- Требует семантики (для .NET — Roslyn, `adr/0009`); синтаксический разбор Roslyn — fallback («пол»).
- Кормит Фазу 2: агент знает целевой шаблон, к которому приводить код.
- Основа арх-линтов Фазы 3.
