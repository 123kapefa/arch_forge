# 0013 — Вход через внешний auth-сервис (Keycloak) с локальным кешем

## Статус
Предложено (2026-11-08). Подписки — отдельно и позже.

## Контекст
arch_forge — локальное приложение (`adr/0002`): целевой код не покидает машину. Для пользователей, учётных записей и в будущем подписок есть отдельный сервис авторизации на Keycloak (`auth_service`: проект = realm, приложение = client, права объявляются в коде, пакеты `Platform.Authentication*`). Приложение должно уметь работать без постоянной сети.

## Решение
1. **Вход по сети один раз.** При первом запуске пользователь входит через auth-сервис (OIDC, браузер). Приложение получает токены.
2. **Дальше — локально.** Токены и сведения о пользователе хранятся на машине в защищённом хранилище ОС (Keychain / Credential Manager), не в файле проекта и не в Git. Повторные запуски не требуют сети, пока кеш действителен.
3. **Обновление в фоне.** Когда сеть есть, refresh-токен продлевает сессию. Сети нет — работаем по кешу.
4. **Срок автономной работы ограничен** (льготный период, значение задаём настройкой; по умолчанию предлагается 14 дней). После него нужен новый онлайн-вход. Отзыв доступа на сервере вступает в силу при ближайшем подключении.
5. **Граница данных.** В auth-сервис уходят только данные входа. Целевой код, карты и профили (`adr/0012`) наружу не передаются.
6. **Где проверяется вход.** Gateway `Map` принимает токен и применяет права; `Analysis` остаётся без состояния и внутренним.

## Не входит
Подписки и тарифы (проектируются позже поверх тех же прав); регистрация собственных пользователей внутри arch_forge; офлайн-режим без входа вообще (если он нужен для open-source/локальной сборки — отдельное решение).

## Альтернативы
- **Вход при каждом запуске.** Ломает работу без сети.
- **Только локальный пароль.** Нет единых пользователей и отзыва доступа.
- **Бессрочный кеш.** Отозванный пользователь остаётся с доступом навсегда.

## Последствия
- Нужна безопасная работа с токенами на клиенте и проверка часов (защита от откручивания даты).
- Нужен режим «без входа» хотя бы для разработки (флаг в конфиге), иначе локальный запуск и тесты зависят от Keycloak.

## Открытые вопросы
- Длина льготного периода и что видно пользователю в последние дни.
- Нужен ли режим без входа в публичной сборке.
- Где хранить токены, если приложение запущено как сайдкар без доступа к хранилищу ОС.
