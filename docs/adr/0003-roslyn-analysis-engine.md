# 0003 — Roslyn / MSBuildWorkspace как движок анализа

## Статус
Заменён на [0006](0006-continue-archlens-stack.md) (2026-08-14): основной движок — tree-sitter (полиглот); Roslyn остаётся как опциональный precision-слой для .NET-семантики. Ниже — исходное решение (для истории).

Исходно: Принято.

## Контекст
Нужно надёжно разбирать `.sln/.csproj`, неймспейсы, типы и зависимости C#. Это определяет язык всего бэкенда.

## Решение
Движок анализа — **.NET + Roslyn (Microsoft.CodeAnalysis) / MSBuildWorkspace**. Загружаем солюшн/проекты, извлекаем проекты, ссылки, неймспейсы, типы и зависимости.

## Альтернативы
- **Переписать анализ на JS/Rust.** Отклонено: потеря семантической точности Roslyn, дублирование того, что MSBuild/Roslyn дают из коробки.
- **Парсинг файлов регэкспами.** Отклонено: хрупко, не понимает семантику ссылок и типов.

## Последствия
- Бэкенд фиксирован на .NET — это же удобно для запуска локальных .NET-целей.
- MVP-0 опирается на project references и неймспейсы (низкий риск, хорошо поддержано).
- Более глубокие связи (класс-уровень, межсервисные) надстраиваются поверх той же модели на поздних вехах.
