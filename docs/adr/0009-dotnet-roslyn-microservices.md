# 0009 — .NET-бэк по своду + Roslyn-ядро + декомпозиция Analysis/Map

## Статус
Принято (2026-08-14). Заменяет [0006](0006-continue-archlens-stack.md); возвращает и уточняет направление [0002](0002-local-web-app.md) / [0003](0003-roslyn-analysis-engine.md).

## Контекст
Ранее (0006) был разворот в стек archlens (Node/TS) как «продолжаем готовое». Это ошибка: пользователь строит бэкенды на **.NET** по документированной методичке (свод Platform Architecture — Clean Architecture + DDD + вертикальные срезы) и хочет продукт на том же стеке. Цель анализа — C#, а лучший движок для C# — Roslyn (нативно на .NET).

## Решение
- **Бэк — .NET/C#** строго по своду: каждый сервис — Domain/Contracts/Core/Infrastructure/Web, вертикальные срезы, `Result<T,Error>`, маркеры `ICommand/ICommandHandler/IEndpoint/AbstractValidator`, само-регистрация `IEndpoint`, `SharedKernel`/PlatformBootstrap.
- **Движок — Roslyn** нативно (см. `docs/roslyn.md`); C#-спайк `archforge-spike` — зародыш ядра.
- **Фронт — свой клиент** на React + React Flow (`@xyflow/react`) на контракте `Map` (`/api/map`); archlens — только референс идей, код не переиспользуется. Детали — `adr/0010`.
- **Микросервисы (по возможностям, не по слоям):**
  - `Analysis` — Roslyn/MSBuild: `путь → IR`. Тяжёлый, async-friendly, изолирован; сюда же позже другие языки.
  - `Map` — пак/линт/проекции/импорты/workspace, отдаёт фронту.
  - Позже: `Agent` (Фаза 2), `Diff/History` (Фаза 3).
  - Шов — общий контракт `ArchForge.Contracts` / IR.
- **Старт** — модульный монолит: `Analysis` и `Map` как отдельные сервисы-проекты в одном solution с жёстким контрактом `путь→IR`; вынос `Analysis` в отдельный деплой/воркер — позже, сменой конфига (философия свода «монолит → выносим при масштабе»).
- **archlens (Node/TS)** — референс идей (IR-модель, «Импорты за кнопкой», раскладка), не кодовая база бэка.

## Альтернативы
- Продолжать archlens на Node/TS (0006). Отклонено: не тот стек, не по своду, полиглот не приоритет (цель — C#).
- Полиглот через tree-sitter как основной движок. Отложено: Roslyn точнее для C#; другие языки — отдельные `Analysis`-сервисы позже.

## Последствия
- Прежние TS-наработки в archlens (роли / тип-уровень / линт) — не бэкенд продукта; логика переносится в `Analysis` на C# (спайк уже это делал).
- `Analysis` тяжёлый (семантика требует сборки) → отдельный сервис/воркер оправдан.
- Скелет solution раскладывается по своду; движок зафиксирован в `docs/roslyn.md`.
