# 0004 — Полный вижн при тонком MVP-0

## Статус
Принято (принцип «полный вижн + тонкий срез» в силе). Уточнение (2026-08-14, `adr/0006`): конкретный «тонкий срез» — теперь следующий инкремент на archlens (милстоны P1-* в `ROADMAP.md` / `docs/plan-phase-1.md`), а не greenfield .NET-MVP.

## Контекст
Замысел большой (все цели, полная глубина, виз + правила + метрики, позже ИИ). Есть риск либо утонуть в объёме, либо, наоборот, «пилить по чуть-чуть» без понимания общей логики. Пользователь хочет видеть всю картину заранее, но двигаться безопасно.

## Решение
Развести **вижн** и **первый код**:

- Вижн фиксируется полностью и сразу — в `docs/VISION.md`, `docs/ROADMAP.md`, `CONTEXT.md`.
- Первый код — тонкий **MVP-0**: один сервис, только слои + плашки (tracer bullet, доказывающий путь «разбор → карта»).

## Альтернативы
- **Сразу строить полную картину** (мультисервис + связи + инфра + метрики). Отклонено: долго, рискованно, нет ранней проверки пути.
- **Пилить фичи без общего вижна.** Отклонено: теряется «куда двигаемся и почему».

## Последствия
- Ранний работающий срез при полной прозрачности замысла.
- Каждая следующая веха — прирост к MVP-0 по `ROADMAP.md`.
- Гарды будущего (якоря на исходник, модульные границы) закладываются уже в MVP-0, чтобы не закрыть двери Фазе 2 и десктопу.
